# MISHU

> BOSS直聘 个人自动化助手，就干两件事：
>
> - **自动投递**（`npm run watch`）：HR 向你发来招呼、你还没看过 → 自动回一份附件简历
> - **主动打招呼**（`npm run greet`）：从推荐岗位里挑和你匹配的 → 大模型逐条写开场白 → 主动联系 HR

---

> ⚠️ **个人自用工具**
>
> - 请只用于**你自己账号**，遵守 BOSS直聘 用户协议 —— 自动化行为可能触发平台风控，**账号风险自负**
> - BOSS 每天打招呼/投递有次数上限，属于平台规则，本工具不绕过
> - 不群发、不替你回复聊天内容；开场白也是一岗一句单独生成，不是模板轰炸

---

## 安装

### 1. 拿代码 + 装依赖

```bash
git clone https://github.com/jamesbow007/MISHU.git
cd MISHU
npm install
```

### 2. 加载 Chrome 扩展

1. 打开 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选项目里的 **`extension/`** 目录
4. 扩展图标出现在工具栏（亮着数字徽章 = 已连上本地服务）

### 3. 登录 BOSS直聘

用你日常那个 Chrome，登录 zhipin.com。

> **不需要**手动开着消息页 —— 工具会自己在后台开页面、用完关掉。

### 4. 用「主动打招呼」才需要：配一个大模型

任何 **OpenAI 兼容接口**都行。复制模板、填上你的 key：

```bash
cp .env.example .env
```

`.env` 里三项改成你自己的（`.env` 不进仓库，只有模板 `.env.example` 会提交）：

```
BASE_URL = "https://api.xxx.com"
API_KEY  = "sk-xxx"
MODEL    = "模型名"
```

自动投递不需要这一步。

## 功能一：自动投递（HR 来招呼 → 自动发简历）

```bash
npm run watch
```

每 5 分钟扫一次「新招呼」里**带红点**的会话（红点 = 你还没点开过），自动发一份附件简历。

- 发送路径和你手动点「发简历 → 确定」一模一样；每一步都核对会话对没对上人，**对不上就停手**
- 发完回服务端确认一次，确认到了才记「已投递」
- 同一个 HR 12 小时内不重复投；失败的跳过记名单，不中断整轮
- 数量不做限制 —— 有多少红点投多少

```bash
npm run watch -- --once --dry-run   # 先干跑：只打印这一轮会投给谁，一个不发
npm run watch:bg                    # 后台跑（脱离终端）
npm run watch:stop                  # 停掉
npm run watch:status                # 看它在不在跑、今日投了几个
```

| 参数 | 作用 |
|---|---|
| `--once` | 只跑一轮就退出 |
| `--dry-run` | 只扫描打印，不投递 |
| `--interval N` | 轮询间隔（秒，默认 300） |
| `--limit N` | 本轮最多投 N 个 |
| `--only <姓名>` | 只投给指定的人（补投用） |
| `--no-verify` | 跳过服务端二次确认（快一点，少了自检） |
| `--tabs` / `--cleanup-tabs` | 查看 / 清理多余的聊天页标签 |

日志：`data/watch.log`；已投名单：`data/auto-deliver-state.json`。

## 功能二：主动打招呼（挑岗位 → 写开场白 → 联系 HR）

一轮的流程：

1. **找岗位** —— 只从职位页的**推荐区**抓：按你简历里的期望职位（比如「大模型算法·深圳」「大模型算法·北京」）推荐的那批
2. **逐个判断** —— 打开岗位详情页读 JD，交给大模型打分：这个岗位和我的简历匹配吗？值不值得打招呼？
3. **写开场白** —— 值得的，大模型**根据你简历的「个人优势」**单独写一句客气的开场白，一岗一句
4. **发出去** —— 在岗位页点「立即沟通 / 继续沟通」，只发**文字**（不附简历）；发完到服务端确认真的发出去了
5. **记账防重复** —— 按 **HR（人）** 去重：同一位 HR 30 天内不会再打扰（哪怕他挂了好几个岗位）；失败的岗位 1 天后才会重试

每个招呼之间随机隔 2~5 分钟；一轮结束歇 5 分钟再来下一轮。节奏、上限都在配置文件里（见下）。

### 先干跑（强烈建议）

```bash
npm run greet -- --dry-run
```

只打印「挑了哪些岗位、打了多少分、开场白长什么样」，**一个都不发**。
看着满意再去掉 `--dry-run`。（干跑也会真实调用大模型，产生少量费用。）

### 实跑

```bash
npm run greet              # 一直跑，Ctrl+C 停
npm run greet -- --once    # 只跑一轮
```

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只看判断和文案，不发 |
| `--once` | 只跑一轮 |
| `--limit N` | 本轮最多打 N 个招呼 |
| `--pick <jobId>` | 只处理指定岗位（补投用） |

日志：`data/greet.log`（`tail -f` 实时跟）；已联系名单：`data/greet-state.json`。

### 配置（可选）

没有配置文件就全用默认值。想改就在 `data/greet-config.json` 写（不存在就新建一个 JSON）：

```json
{
  "intervalMinSec": 120,
  "intervalMaxSec": 300,
  "perRound": 20,
  "dailyLimit": 0,
  "cooldownDays": 30,
  "salaryMinK": 0,
  "pages": 1
}
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `intervalMinSec` / `intervalMaxSec` | 120 / 300 | 两个招呼之间随机间隔（秒） |
| `perRound` | 20 | 每轮最多打几个（0 = 不限） |
| `dailyLimit` | 0 | 每天最多打几个（0 = 不限）。**建议设个值**，给平台每日上限留余量 |
| `cooldownDays` | 30 | 同一位 HR 多久之内不再打扰（天） |
| `salaryMinK` | 0 | 薪资下限（K），低于它的岗位跳过 |
| `pages` | 1 | 每个期望职位翻几页推荐 |

> 每个新岗位都会调用一次大模型；判断结果缓存 24 小时，重复推的岗位不会重复问、重复花钱。

## 遇到问题

**「扩展未响应」**
Chrome 没开，或扩展被停用了 —— 到 `chrome://extensions/` 里点一下 🔄。

**浏览器里 BOSS 页面越开越多？**
正常只会留一个。先 `npm run watch -- --tabs` 看一眼，多了就 `--cleanup-tabs` 清掉。

**greet 偶尔报「详情页打不开」**
偶发的页面导航失败，本轮跳过、下一轮自动再试，不用管；连续大片出现再来查。

**greet 报「not-sent」**
页面点了发送，但服务端没确认到。程序会记成失败、1 天后才重试 —— 重试前建议在网页上人工核对一下那个会话，避免重复发。

**自动投递会洗掉我的未读红点吗？**
会 —— 投简历必须先打开会话，红点随之消失，这是 BOSS 自己的机制。工具不会替你删任何消息。

**改了扩展代码没生效**
Chrome 缓存住了 —— 跑 `npm run ext:reload` 让扩展自己重载。

## 已知限制

- 需要一个**已登录 BOSS直聘**的 Chrome 一直开着
- 猎头岗位没有投递按钮，简历只能从聊天窗口发（本工具走的就是这条路）
- 主动打招呼只发文字；对方回复要简历时，交给「自动投递」或你手动发
- BOSS 改版可能导致页面结构变化、功能失效
